# 网文扫榜工具

<p align="center">
  <img src="assets/icon/app-256.png" width="120" alt="程序图标">
</p>

一个**纯 Dart、零第三方依赖**的网文榜单采集与分析工具：只用 `package:ffi` 直调 Win32
（`user32` / `gdi32`）画界面，不引 Flutter、不引 Qt、不引任何第三方包 ——
连 PNG 编解码、GBK 解码、deflate 压缩都是手写的。

覆盖四个平台：**起点 / 番茄 / 七猫 / 晋江**。

核心不是"抓一次排名"，而是**把同一张榜跨天的历史存下来，看它自己的排名与数据怎么变**，
并给出**可复算的趋势解读** —— 哪几条是事实、哪几条只是候选原因，界面上分开标。

# 功能

## 采集

- **四平台适配器**：起点（www 站 SSR + catid 题材榜）、番茄（`category/list` 接口）、
  七猫（Nuxt 内嵌载荷）、晋江（topten 表格 + gb18030）。
- **四道护栏**，每条都有实测依据：
  1. **域名白名单** —— 逐跳校验，重定向也跑不掉；
  2. **robots 判定** —— 按 user-agent **分组**解析（精确组优先），三态如实上报
     （`fetched` / `notFound` / `unknown`），403 或超时**不谎报允许**；
  3. **限速** —— "预约时间槽"实现，判断与写入之间无 `await`，并发下也真的生效；
  4. **仅元数据** —— 结构上禁止携带正文字段。
- **免登录、不绕反爬**：不模拟浏览器、不用 Cookie、不碰验证码；
  遇到挑战页**停手并如实记录**，不做绕过。
- **番茄字体反爬已解开**：那份字体是思源黑体 SC 的子集，把字形栅格化后做最近邻 +
  用字形在 em 框里的绝对位置消歧，得到完整映射；**绑定字体哈希**，哈希对不上就不解码，
  退回 `〔名待补〕`。
- **书封面**（可关的"额外一小步"）。四个平台的取法**不一样**，如实列出来：

  | 平台 | 封面从哪来 | 额外请求 |
  |---|---|---|
  | 起点 | 榜单行里就有；且地址是 `bookId` 的**纯函数**（`/qdbimg/349573/{id}/150`），**直接推导** | **0**（连页面都不用抓） |
  | 番茄 | 榜单接口**不给**封面 → 去书籍页抠 `novel-pic` 那张（225×300） | 每本书 1 次 |
  | 七猫 | 同上 → 去书籍页抠 `readerCover` 那张（195×260） | 每本书 1 次 |
  | 晋江 | 书籍页里**没有**封面 | —— 画占位卡 |

  ★ 起点那条"推导"很重要：**之前采集的旧快照里没有封面字段**，
  靠推导才能让老数据也有封面（不用重扫）。

  ★ 番茄/七猫是"扒书籍页"而不是"抓页面第一张图"：书籍页上有"猜你喜欢"，
  那些封面同样落在图片 CDN 上，**显示错的书封面比不显示更糟**。
  所以只认"只属于本书封面"的路径特征（两家各抓两次验证过稳定）。

  取图一律**懒加载 + 永久缓存**：只有滚动到可见的行才会入队，每本书**一辈子只下一次**
  （按 `bookId` 落盘到 `out/扫榜/_covers/`）。**只认白名单域名**，
  跨域重定向不跟随，单张超过 4 MB 直接放弃。取不到就画占位卡。

## 本地数据库

- `out/扫榜/index.json`：**快照清单 + 保留策略 + 图片附件登记**，采集即入库。
- **加载自愈**：磁盘上有、索引里没有的快照会自动补进来并落盘。
- **保留策略按系列**（同平台 + 同榜 + 同题材）计，不是按榜名 ——
  否则同一张榜的多个题材会互相抢名额。
- **隐藏 ≠ 删除**：被隐藏的榜只是不在侧栏显示，数据、索引、附件一个都不动。

## 分析与解读

- **榜单明细**：`# / 封面 / 书名 / 作者 / 题材 / 指标 / 备注 / 链接`；
  封面是 **36×48 的严格 3:4 缩略图**（按别的比例缩放会把书封拉变形）；
  **书名与「打开」按钮都能点**，直接打开这本书的详情页；没有封面地址的书画占位卡
  （首字 + 由书名哈希决定的稳定配色），所以每一行的封面格宽度始终一致。
- **历史对比**：同一张榜**自己的历史**按时序排开 —— **每本书各自一条折线**
  + 逐期名次与数据表（首期 / 上期 / 本期 / 较上期 / 较首期 / 字数 / 字数变化）。
  折线可以换**看图口径**：`排名`（y 轴反向，越小越靠上）/ `指标`（月票、热度、积分…）/
  `字数`；还能选画 `6 / 12 / 全部` 条。两种口径的选线规则不同 ——
  排名看"名次最好 + 波动最大"，指标/字数看"**变化最大**"（涨得最猛、跌得最狠的才值得看）。
  某期掉榜就**真的断开**，不连到轴上（连上去等于画出一条不存在的轨迹）。
  绝不回到"用户手挑两份文件"那套语义。
- **趋势解读**：每条原因都由**规则**从可复算的数字触发，带三样东西 ——
  **证据**（用了哪几个数）、**置信度**（较强 / 中等 / 较弱）、**边界**（本工具看不到什么）。
  界面上**事实（蓝点）与候选原因（橙点）视觉分开**，卡片底部常驻"需人工核实"。
  **期数 < 3 就不猜**，只说"这只是两期之差"。
- **跨榜分析**：一张**各平台主流题材对比表** —— 行是平台，列是
  `题材数 / 条数 / 集中度（前三题材占比，带条）/ 主流题材前 3（带各自占比）`。
  点行即可切换下面那张"该平台的完整题材分布"（条形 + 占比 + 该题材最好名次）。
  另外还有"同时出现在多个榜的书"（跨榜信号，可滚动）。
  **各平台的分类体系不同，名字对不齐**（起点 玄幻/仙侠/都市，番茄 都市高武/架空历史，
  晋江整站只有"言情"）—— 所以对比的是**集中度**，不是"谁的玄幻更多"。
  只有一个题材的平台会标注"（该平台未细分题材）"，免得 100% 被读成"极度集中"。

## 界面

- **深色 / 浅色两套主题**，顶栏一键切换，偏好写在 `out/ui.json`。
  浅色档不是把深色反过来：底色带蓝（纯白会让卡片"浮不起来"）、主色更深
  （白底对比度 4.6:1）、投影只能用淡灰蓝（深黑会成一圈脏边）。
- **侧栏按平台折叠**（宽 280、行高 62、榜名 15px）；悬停某行右侧浮出"⊘"把整张榜
  **隐藏**，底部「已隐藏 N 项 · 管理」可恢复。
- **扫榜设置**：折叠树（平台 → 榜 → 题材，可搜索过滤，**没有子节点的行不画折叠箭头**）+
  三态选中（整行蓝框：全选 = 选中底 + 主色描边 + 左侧竖条，部分选中 = 主色淡底）+
  **每个榜有自己的本数**（`− N 本 +`，点数字可直接输入任意值），
  顶栏另有"所有已选榜统一改"的批量步进器。
- **数据管理窗**：左栏系列（平台 · 榜 · 题材 + 份数 + 日期区间），
  右栏该系列的每一期（日期 / 条数 / 附件 / 占用，每行可删），
  顶部"每系列保留 N 份"；**破坏性动作先报数再执行**。
- **字号与行高随窗口缩放**：基准 1240×800，上限 **1.4×**。缩放曲线带权重（0.52）
  与 2% 量化 —— 窗口拉大一截才跳一小档，不会"突然大一圈"，拖动时也不抖。
- **「榜单明细」整表放大 1.5 倍**（列宽 / 字号 / 行高 / 封面**同乘一个数**，
  版面比例不变），而且是**自适应**的：
  **窗口够宽就用到满 1.5 倍**（行高 126、字号 29、封面 76×101）；
  **窗口不够就等比缩到刚好放得下**（下限 1.0 倍）——
  宁可小一号也不让「链接」列被挤出屏幕（看不到按钮就等于点不开）。
  放得下时表格还会**撑满可用宽**（右侧不留空缺，余量给「书名」列）。
  只有在缩到下限 1.0 还放不下的极窄窗里才横向滚动
  （点滚动条两侧翻页 / 滚轮停在滚动条上 / 触摸板双指横扫 / 倾斜滚轮）。
- **每本书**：整行都可点（不用去点那个小按钮），悬停整行高亮、书名加下划线，
  点开的是系统默认浏览器里的书籍详情页。
  **打开就是一条路：把快照里的地址原样交给系统默认浏览器**（`ShellExecuteW`
  带上本窗口句柄，新窗口的前台归属才明确）；失败再走 cmd 的 `start`
  （另一套关联解析）。成功/失败都在**窗口里弹一条提示条**（状态栏会被浏览器挡住），
  并且每次都写 `out/扫榜/_open_log.txt`（含返回码与走了哪条路）——
  "用户说不行、我这边验通"这类问题只能靠留证据。全都不通时**弹框**说明
  并把地址放进剪贴板。
- **★★ 为什么"直接打开"才是对的：那套"聪明"的做法反而更糟**（2026-10-02 全部删掉）。
  用户原话："**直接把链接放入就行了，不要搞别的**"。之前这里叠了两层：
  - **起点窄窗启动页**：起点主站 www 有 WAF（202 挑战页），移动站 m 站能开，
    但 m 站 `<head>` 里有**桌面端回跳**（`outerWidth > 1024` 就跳回 www）。
    于是生成本地 HTML、用 760px 弹窗去开 m 站 —— 可 `file://` 页面上的
    `window.open` **基本必被 Chromium 弹窗拦截**，用户看到的是一张**空白本地页**。
  - **隔离实例**：为了绕开"Edge 以管理员身份常驻"的 UIPI 冲突，
    用 `--user-data-dir=<私有目录>` 起了一个**全新 profile** 的 Edge ——
    全新 profile 会走 Edge 的**首次运行流程**（欢迎页 / 导入数据），
    而且那个 profile 会在用户数据目录里长到几十 MB。
  两条路都在"用户想看的那一页"**前面加了一层东西**，表现就是"跳不到详情页"。
  现在没有了：**地址进、地址进浏览器，中间零加工**（CSV 导出里的链接列也原样输出）。
  代价是起点主站的 202 挑战页要由**浏览器自己**去过 —— 那本来就是 WAF 的设计，
  真实浏览器会跑完那段 JS。若你的 Edge 是以管理员身份常驻的，系统会弹
  "是否用普通权限重启"：点「是」即可（或者干脆别用管理员身份开浏览器）。
- **备注列只放"这本书现在是什么状态"**（连载 / 完结），不塞简介、也不塞
  `榜变 -1` 这类**平台内部字段名**（读者看不懂，还把状态挤到后面）。
  按优先级认：番茄 `creationStatus`（0=完结）→ 起点 `isOver` / www 站 `<span>`（1=完结 /
  原文"连载"）→ 七猫 `isOver` → 晋江 `status`；一个都认不出就写 `-`（不编）。
  ★ **起点的移动站降级路径拿不到状态**：移动站 `records` 只有
  `catId/bName/rankNum/cat/cnt/bid/subCat/bAuth/desc`，**没有连载/完结字段**
  （实测 0 命中），所以走降级时起点备注会是 `-`，扫榜质量摘要里会如实写明；
  装上 Edge/WebView2 走 www 站即可显示（www 站行内有 `<span>连载</span>`）。

## 导入导出

导出菜单**按用途分三块**（前两类产物口径完全不同，混在一起用户分不清
"我导出的到底是这一份榜，还是这个榜的历史"；第三类是"往哪导"的设置）：

**★ 导出是"一键出文件"**（2026-10-02 重做）：点菜单里任何一项 →
文件**直接落到导出目录** → 弹一个完成提示。**中间不再弹文件夹选择框。**

> 为什么改：上一版是"每导出一次都弹文件夹框选落点"。用户实测判定
> **根本不可用**（原话："导出根本无法使用，整个导出功能重做"）——
> 一次导出要点三次对话框（选目录 → 完成提示 → 打开目录），
> 而"选目录"这一步只要弹不出来 / 弹到主窗后面 / 选到不可写的盘，
> 表现就是"导出没反应"；而且**模态框让自动化测试根本没法跑**。
> 现在导出目录是**一处设置**：默认 `out\导出`，想换就点菜单里的
> 「设置导出位置…」—— 那是**唯一**会弹文件夹框的地方。
> 落点不可写时**如实退回默认目录**并在状态栏说明，绝不把写不进去的路径
> 交给导出逻辑。回归脚本 `bin/_t_export_flow.dart` 守这条，
> 它最关键的断言是"**它跑得完**"：谁把弹框加回导出路径，它会直接挂住。

**打开链接会"真的去确认"**（2026-10-02/03，两轮才做实）：`ShellExecuteW`
返回 >32 只代表"请求交给系统了"。用户录屏暴露了两种假成功：
  · Edge 起来了、**停在"新建标签页"**（页面根本没导航过去）；
  · 窗口标题还是 **"无标题"**（页面没加载完）。
所以点「打开」之后，会**依次试四条路**，每一步都确认"页面真的加载了"才报成功：
  ① `ShellExecuteW`（系统关联）；
  ② **直接起注册表里那个浏览器 exe**（绕开 shell 关联 —— 实测有机器上
     `ShellExecuteW` 会把 URL 弄丢）；
  ③ **`--new-window` 强制开新窗口**（Chromium 系都认 —— 实测有机器上 Edge
     在后台跑着但不开窗，URL 交给后台实例就被吞了，只能强制开窗）；
  ④ `cmd start`（又一套关联解析）。

"确认"的判据（**两个假阳性都真踩过**，所以写得比较严）：
  · 浏览器窗口 = **类名 + 进程名 + 非空标题**三个都对
    （只看进程名会挑到 Edge 的辅助窗口，标题是空的；只看类名会认到
     Electron 应用 —— 它们也用 `Chrome_WidgetWin_1`）；
  · 标题必须**对得上这本书或这个平台**（书名前 4 字 / 起点·番茄·七猫·晋江）——
    否则 Edge 的"**还原页面**"提示窗口也会被当成"已打开"；
  · "新建标签页 / 无标题 / New Tab / 空标题"一律算**没加载**，继续等（最多 10 秒）。

**★★ 还有一种情况：Edge 以管理员身份运行（2026-10-03 实测根因）。**
此时普通权限的程序**没法**把网址交给管理员程序 —— Windows 的**完整性级别隔离
（UIPI）**会拦下，Edge 弹「现有实例正在以提升的权限运行，是否用普通权限重启？」
（窗口类 `#32770`、标题 `Microsoft Edge`），用户点「否」→ 页面永不出现，
而 `ShellExecuteW` 照样返回 42。

程序会**认出那个对话框**（`#32770` + 标题含 Microsoft Edge）并**如实说**。
★ **不替用户点它**（第 39 轮撤回）：那个「是」= "用普通权限重启 Edge"，
点下去会把用户**开着的所有 Edge 窗口一起关掉**，而页面照样没打开 ——
**代价远大于收益**。那个框是 Edge 自己的，不该由我们去点。
★ 实测（2026-10-03）：**这条链路本身是通的** —— 用程序自己的窗口当 owner
  调 `openExternal`，Edge 里的页面标题确实变成了那本书。用户之前失败是因为
  **当时那个 Edge 实例是管理员身份**；现在 Edge 已是普通权限。
  ★ 另一个实测现象：用户的 Edge 开着**多个窗口**时，新页面可能开在
  **另一个窗口/后台标签**里（我抓到的窗口标题在多个窗口间来回跳）——
  所以失败提示里会明确让用户"先看任务栏有没有 Edge 在闪"。

★ 这里原本还有一条"用 `runas` 把浏览器按提升权限起起来"的路 —— **已删除**：
  它会弹 **UAC 确认框**（用户明确嫌弹窗多），而自动点「是」已经能解决。
  另外"打开前先读浏览器**令牌**"确认权限（`TokenElevation`）也会写进日志 ——
  这是硬证据；★ 曾用"`OpenProcess` 是否被拒"来判断，拿已知答案校准后**不成立**，
  那个判据已整个删掉。
- 只给**一条提示条**（不再叠系统 MessageBox —— 那和提示条说的是同一件事，
  用户反馈"弹窗太多了"；本项目自己的原则也是"主流程里不许有模态对话框"），
  内容给**两个**明确办法：
  ① **右键本工具 → 以管理员身份运行**（推荐，一劳永逸）；
  ② 在 Edge 那个框里点「**是(Y)**」（用普通权限重启 Edge）。
★ **试过但撤掉的做法**：曾经想"事前判断浏览器是否提权"（`OpenProcess`
  是否被拒）来**避免**弹出那个框 —— 用 explorer / svchost / pid 4 校准后
  发现**判据不成立**（SYSTEM 级的 svchost 照样能打开，且 `GetLastError()`
  会被后续 FFI 调用冲掉）。**一个会误判的预检比没有预检更糟**，所以撤了。

四条路都不行（且不是权限冲突）时**如实说**"浏览器起来了，但页面没打开"，
并提示把 Edge **完全退出**（含托盘）再试 / 关掉 Edge 的「启动增强」/
临时关掉下载类工具（如 IDM）的浏览器插件。
每次打开都把**当时的可见顶层窗口清单**与**浏览器窗口标题**写进
`out/扫榜/_open_log.txt` —— 这类问题只能靠现场证据。

**从 cmd 启动不会再把程序和那个控制台绑在一起**：GUI 程序从 cmd/.cmd 启动时会被
附着到父控制台，那个黑底带滚动条的窗口关掉会**连程序一起杀**。启动时
`FreeConsole()` 主动脱离（记录写在 `out/扫榜/_startup.txt`）。

**外链只放行 http / https**（`safeExternalUrl`）：书链来自**抓取结果**，
而它会被交给 `ShellExecuteW` —— 那是"按 shell 关联执行"的入口，
`file:///C:/…/calc.exe` 或裸路径 `C://evil.exe` 会被**真的运行起来**。
白名单之外的地址一律不打开、只如实说明。生成的单文件网页同理
（模板里的 `extLink()` 只放行 http(s)，并统一带 `rel="noopener noreferrer"`）。

**落盘这一步是加固过的**（2026-10-02）：先写临时名再**改名替换**
（绕开"文件被看图软件/杀软/索引器占着"导致的 `errno = 32 / 5`）→
失败**原地重试一次** → 还失败就**退回默认导出目录** `out\导出`，
并在完成框里**说明换到哪了**。因为"偶发占用"这类问题复现不了，
只能让**导出这件事一定有结果**，而不是把异常甩给用户。
> 用户报过：`导出榜单图失败：PathAccessException ... errno = 5`（目标是桌面）。
> 本机同一路径、同一份快照、同一个 exe 都写得进去 —— 属于偶发占用。

**① 榜单（这一份快照）**

**导出位置两种模式**（菜单第三组里切换）：
「设置导出位置…」设一个固定落点（默认 `out\导出`），
「每次导出前先问文件夹（当前：开/关）」打开后每次导出都先弹框
（**取消 = 本次不导出**，绝不悄悄换地方存）。默认是**关**，也就是一键出文件。

**导出的图不会再把书名压扁**（2026-10-03）：榜单图/趋势图的画布宽是
**逻辑宽 × 缩放**（与窗口建窗同一套约定）。原来画布写死 980、内容却乘
`Metrics.factor` —— 在 150% 缩放的屏上列宽合计 1398 > 可用 908，
于是走"硬约束压缩"，而**书名列是 stretch 列**、第一个被压到下限
（实测 314 → 54 像素，图里只剩一个字 + 省略号）。

| 导出 | 说明 |
|---|---|
| Excel 表格（.xlsx） | **Excel 原生格式**，三张表：榜单明细 / 指标口径 / 榜单信息。字符串走 `inlineStr`，**结构上不可能是公式**（CSV 只能靠前置单引号打补丁）；数字是真数值。零依赖手写 ZIP + OOXML（复用 `png.dart` 的手写 deflate 与 CRC32） |
| CSV 明细表 | 带 BOM（防 Excel 中文乱码），公式注入已消毒，含**详情页链接**列 |
| JSON（单份快照 + 分析） | 这一份的条目 + 分析结果 |
| 榜单图片（PNG 长图） | 整榜长图，不受窗口可视区限制；**列与界面的「榜单明细」完全一致** |
| 附件（图片 / 文本） | 把当前快照的附件复制到导出目录 |

> 榜单图的列 = `# / 封面 / 书名 / 作者 / 题材 / 指标 / 备注`，
> 表头文字、单元格文本、列宽基准、对齐方式、谁吃余量**全部只有一份定义**
> （`lib/ui/board_text.dart`），界面与导出图共用 —— 改了界面导出图一定跟着变。
> 唯一的例外是「链接」：它在界面里是个**可点按钮**，静态图里画个"打开"没有意义，
> 所以导出图不画它（图脚会说明"详情页地址见 CSV/JSON 导出"）。
> 导出前会**先把封面备齐**（走同一个限速 + 落盘缓存），所以图里是真封面而不是占位卡。

> **导出完成后会弹一个明确的提示框**（写明导出了什么、存到哪、多大）。
> 之所以要有它：导出后会顺手打开导出目录，**那个窗口会抢走注意力**，
> 只看状态栏等于没提示。

**② 趋势分析 / 历史对比（跨期产物）**

| 导出 | 说明 |
|---|---|
| 趋势图（PNG，含解读） | 折线 + **趋势解读块** |
| 全部快照汇总（含两两对比） | 概览 + 各系列的两两对比 |

**③ 导出位置 —— 没有可"预设"的东西**

> ★ 第 21 轮**删掉**了原来的「修改导出位置…」和「恢复默认位置（out\导出）」两项。
> 原因是它们与"每次导出都弹框选目录"是**互斥的两套语义**，共用一个设置字段
> 互相污染：旧项把 `exportDir` 当"固定导出目录"，而弹框机制把**每次选中的目录**
> 写回同一字段当"起始位置"—— 于是导出过一次之后，"固定目录"就变成了随手选的
> 地方，两个菜单项与弹框开始打架，用户看到的现象就是**"导出失效"**。
> 现在只保留一套：**导出目录由你当场在对话框里决定**，唯一被记住的是
> "上次选过哪"（只影响弹框初始位置）。所以这一组不需要、也不该有菜单项，
> 菜单里只留一行灰字说明（"以上都会先让您选文件夹（上次：X）"）。

> **导出流程**：点某个导出项 → **先弹文件夹选择框** → 选中后写到该目录 →
> 弹信息框告知结果 → 打开该目录。
> 之所以每次都要问（而不是"先去菜单预设好再来导"）：用户原话是
> "点击导出，选中导出格式，然后弹出选择导出到哪个文件夹，最后成功导出到对应文件夹"
> —— 路径选择是**导出流程里的一步**，不该藏在别处。
>
> **取消 = 什么都不做**：在文件夹框点"取消"会**直接中止本次导出**，
> 不会悄悄落到默认目录。宁可什么都不发生，也不能"点了取消东西还是出来"。
>
> **落点与起始位置严格分开**（这是第 21 轮修复的核心）：
>   - **落点** = 本次对话框返回的那个目录，**只由这一次的选择决定**；
>   - **起始位置** = `settings.lastExportDir`（存 `out/ui.json` 的 `last_export_dir`，
>     兼容老键名 `export_dir`），**只决定下次弹框停在哪**，绝不参与"这回导到哪"。
>
> 这两者混用就是当初"导出失效"的根因；现在互不污染。
> 目录**不可用**（盘没插 / 被删且建不出来）时回退默认目录，且**不抛异常**。
> 菜单分组标题会写出"上次"用的目录，一眼能看到上次导到哪了。

> ★★ **2026-09-28：文件夹框弹不出来的真根因是 COM 没初始化**（用户报
> "导出依旧无法导出，**选择任何文件夹都不行**"）。
> `SHBrowseForFolderW` 配 `BIF_NEWDIALOGSTYLE` 时，微软文档明确要求
> **调用线程必须先 `CoInitialize`/`OleInitialize`**。本项目 UI 线程此前
> **从没**初始化过 COM —— `cover_image.dart` 里那次 `CoInitializeEx` 只发生在
> **取封面**那条路上，用户若在封面还没解码前就导出，COM 就是没初始化的，
> 于是**文件夹框弹不出来、或选完拿不到可用路径** → 看起来就是"选哪个目录都没用"。
> 修法（`ensureComInitialized`）：
>   1. `App.run()` 在**消息循环之前**就把 UI 线程按 STA 初始化
>      （S_OK / S_FALSE / RPC_E_CHANGED_MODE 都算可用）；
>   2. `pickFolderDialog` 里**再兜一次**，并做**两次尝试**：
>      先新式框（`NEWDIALOGSTYLE+USENEWUI`），拿不到就退**旧式框**
>      （不带 `NEWDIALOGSTYLE`，对 COM 无额外要求，最可靠）；
>   3. 起始目录改用 `SHParseDisplayName` 把上次目录解析成 PIDL 塞进
>      `pidlRoot` —— `BROWSEINFOW` 没有 `lpstrInitialDir` 那种字段，
>      这是"从上次目录打开"的唯一正路（解析失败就退回桌面根，绝不让框失败）。

导入：**图片**存为该快照的附件（文件选择框，起始目录可在菜单里设）、
**粘贴文本**存为附件文本（读剪贴板）。
附件挂在**稳定 id** 上（`{source}|{board}|{cat}|{日期}`），重启后仍能找回；
重名自动加 `_2` / `_3` 后缀，绝不覆盖。

> **每本书都带详情页链接，点一下就跳**：CSV/JSON 里有 `链接` 字段；
> 界面「榜单明细」的**整行都能点**（不只有那个小按钮），点书名也行。
> 起点旧快照里的 `book.qidian.com/info/{id}/` 会在出站前**自动规范成
> `m.qidian.com/book/{id}/`**（旧链经 302 会被 WAF 拦成 202 挑战页），
> 所以不用重扫也能点开。

# 使用

## 从源码跑起来

只需要 **Dart SDK ≥ 3.0**（没有任何第三方依赖）：

```bash
dart pub get

# 桌面软件（Windows）
dart run bin/main.dart out

# 命令行：先看有哪些榜（本地枚举，不联网），再抓一轮
dart run bin/scan.dart boards
dart run bin/scan.dart sweep --selftest-trend   # 16 次请求，约 35 秒

# 生成单文件网页并打开
dart run bin/page.dart --open
```

> 数据目录 `out/` 是**外置**的（与工作目录同级，不在仓库里）：跑一次采集就自动建好
> —— 快照 + `index.json` 索引 + 报告 + 附件。重打包 exe 不会覆盖它。

## 命令行

| 命令 | 作用 |
|---|---|
| `dart run bin/scan.dart boards` | 本地枚举平台 / 榜 / 题材，**不联网** |
| `dart run bin/scan.dart scan --source qidian --board 月票榜 --category 玄幻` | 抓单个榜 |
| `dart run bin/scan.dart sweep --selftest-trend` | 一轮周扫（16 次请求，约 35 秒） |
| `dart run bin/page.dart [--open]` | 生成自包含的单文件网页 |
| `dart run bin/main.dart [数据目录]` | 起 GUI（默认数据目录 `out`） |

退出码沿用 oh-story 的红线约定：`0` 全成 / `1` 零产物 / `2` 部分产物。

## 桌面软件：单 exe，双击就开

```cmd
build_exe.cmd
```

产出 `build\网文扫榜工具.exe`（约 8.1 MB，单文件、GUI 子系统、不弹黑框）。

**为什么不用 `dart compile exe`**：某些沙箱环境里 `dart.exe` spawn 子进程时管道句柄会被耗尽，
一律报 `CreateFile failed 231 (所有的管道范例都在使用中)` + `process_win.cc:744`，
且**与路径是否为中文无关**。所以 `build_exe.cmd` 走等价的三步手工链路：

| 步骤 | 命令 | 作用 |
|---|---|---|
| 1 | `dartaotruntime gen_kernel_aot.dart.snapshot … --target-os=windows --aot` | Dart → `program.dill` |
| 2 | `gen_snapshot.exe --snapshot-kind=app-aot-elf --elf=snapshot.aot program.dill` | dill → 机器码 ELF |
| 3 | `tool/wrap_pe.dart` | 把 ELF 作为 `snapshot` 节追加进 `dartaotruntime.exe` |

第 3 步是手工复刻 `pkg/dart2native/lib/dart2native_pe.dart`（逐行对照实现），
顺手把可选头的 Subsystem 从 `CONSOLE(3)` 改成 `WINDOWS_GUI(2)` ——
否则双击 exe 会**额外弹一个黑色控制台框**。

打包链的最后一步是 **嵌图标**（`[5/5] 嵌图标`）：`tool/embed_icon.ps1` 直接调 Win32 资源 API
（`BeginUpdateResource` → `UpdateResource` → `EndUpdateResource`）把 `assets/icon/app.ico`
写进 exe（`RT_ICON` + `RT_GROUP_ICON`），资源管理器 / 任务栏 / 快捷方式上显示的就是它；
**不依赖 SDK 或 rcedit**，也**不删原有资源**（manifest、版本信息原样保留）。
没有 ico 就跳过，嵌失败只警告不打断打包。图标怎么来的见 [`assets/icon/README.md`](assets/icon/README.md)。

打包链的**最后一步是自动部署**（`[6/6] 部署到发布版`）：把成品同步到
`build\发布版\网文扫榜工具.exe`（旧版先备份）。这一步**不能省** ——
用户不会去 `build\` 里找新 exe，他只点「发布版」那个；只打包不部署，
他看到的还是旧版，然后报"改了怎么还是老样子"。这件事已经栽过两次，
所以现在**打包与部署是一个动作**。

> 五个坑：
> ① `gen_snapshot.exe` **不能加 `--aot`**（会报 `Unrecognized flags: aot`）。
> ② `build_exe.cmd` 里的中文注释必须存成 **GBK** —— cmd 按当前代码页读脚本，
> 存 UTF-8 会让注释里的括号**截断 `if` 语句块**，报一堆"不是内部或外部命令"。
> ③ 覆盖 exe 时若报 `Cannot open file ... errno = 32`（被 Defender/索引器持有读句柄），
> **先写到临时名再改名覆盖**即可 —— 改名替换不受读句柄阻挡。
> ④ **代码页不对时，GBK 脚本里的中文字面量会被解成 U+FFFD** ——
> 于是 `copy` 报"复制成功"，文件却落进一个 `������` 的垃圾目录（实测踩到）。
> 所以凡是要拼中文路径的步骤都**别写在批处理里**：部署这一步改成了
> `tool/deploy_release.dart`（Dart 源码是 UTF-8，字符串不受代码页影响），
> 而且它会**逐字节校验**部署结果 —— 不校验等于没部署。
> ⑤ 判断"某个路径能不能用"别靠 `findstr` 之类的预测（字符类在 cmd 下不可靠，
> 实测 errorlevel 恒为 1）—— **先试着建一次，看结果**才准。

## 网页：单文件，双击就开

页面上还有两件"不用回桌面端"的事：
- **点书名看详情**：弹面板显示这本书的指标、其他字段、**各期名次变化**
  （从内嵌的 `D.comparisons` 里算，不发任何请求），外链只是面板里的一个出口；
- **导出当前榜 CSV**：三条口径与桌面端 `exporters.dart` **完全一致**
  （公式注入消毒 / BOM / RFC 4180 引号），否则两处导出的 CSV 会不一样。
  按钮走 `data-act` + 事件委托，**没有内联 `onclick`**（那会逼 CSP 开 `unsafe-inline`）。

`开始.cmd` 选 `3`（先抓一轮，再生成网页并用默认浏览器打开）。
生成物是一个自包含文件 `榜单页.html`（数据全部内嵌，约 1 MB）：
不用联网、不用起服务、拷到别的电脑也能直接看。

页面里有：概览（各平台快照数 / 按平台分列的题材分布 / 跨榜信号）、
单榜详情（质量摘要、robots 判定、来源链接、**指标口径声明**、题材分布、热词、榜单明细）、
以及"对比基准"差分。

# 设计取舍

几条**刻意**的做法，都带着"为什么"：

- **不装成能用**：样本不足就报 sparse；书名被字体混淆就标 `〔名待补〕` 且**不算热词**
  （拿乱码算词频会得到根本不存在的规律）；robots 判定与质量摘要一律如实带出，不报喜藏忧。
- **数字必须可复算，原因必须标明是推断**：趋势解读里事实与候选原因视觉分开，
  每条带证据 + 置信度 + 边界；期数 < 3 就不猜。
- **破坏性动作要报数**：保留策略删了几份、导出少了几行，都要在状态栏 / 图里写出来；
  确认框写清"删几期、释放多少"，且**默认按钮落在"否"**。
- **涨跌语义**：绿 = 表现变好（新上榜 / 排名上升），红 = 表现变差（掉榜 / 下降）——
  与 A 股涨跌色相反，因为它衡量的是"表现好坏"而不是价格。
- **零依赖**：PNG 编解码（含真 deflate）、GBK 解码、GB18030 表、JSON 之外的解析全部手写，
  只为"拷过去就能跑"。
- **数据目录外置**：exe 只是壳，数据在磁盘上；重打包不会覆盖用户数据。

# 已知限制（不装成能用）

- 起点公开 SSR 每榜只有 20 条，**所有 query 参数与翻页都不生效**（17 组实测）；
  再要更多只能走 ajax，而 `/majax/*` 被 robots 禁 → 按 20 条设计。
- 番茄 `rank_version` 是时间戳，**有效期与轮换规律未验证**；每次运行先从 `/rank` 页取一次。
- 番茄字体解码表**绑定字体哈希**；哈希对不上就不解码，退回 `〔名待补〕`。
- 起点首订 / 均订 / 追读属付费侧，公开榜页没有 → "能不能赚钱"这类判断本工具给不出。
- **真正的跨日趋势要连续几天各抓一次**才有；`--selftest-trend` 只是用两个不同榜验证渲染。
- **「榜单明细」的放大倍数随窗口变**：窗口够宽（约 2300px 以上，比如 2560 宽的屏
  最大化）就是完整的 **1.5 倍**；窗口变窄时**等比缩小**到刚好放得下（下限 1.0 倍）——
  宁可小一号也不让「链接」列被挤出屏幕。所以"8 列全可见"是**常态**，
  只有缩到 1.0 倍还放不下的极窄窗（约 1000px 以下）才需要横向滚动。
  这是"看得全"与"放得大"之间的取舍，选了前者。
- 刺猬猫、短剧 / 红果、知乎盐选未做。
- 合规边界如实保留、**没有消除**：起点 robots 点名拒绝 `ClaudeBot` / `ChatGPT-User` / `GPTbot`，
  本工具用 Chrome UA 落在 `User-Agent: *` 组（`/rank/` 允许）—— 这一条由使用者自行判断。

| 约束 | 做法 |
|---|---|

| 不跟丢白名单 | 跨域重定向**不跟随** |

## 1. 「打开链接」：从"假成功"到"如实说"

这一条被用户连续追了四轮，教训最贵，单独记。

### 现在做什么（多条路依次试，每条都确认"页面真的加载了"）

```
点「打开」
 ├─ 0. 前置：读令牌记录浏览器权限（TokenElevation，硬证据）
 ├─ 1. safeExternalUrl() 协议白名单（只放行 http/https + 必须有 host）
 ├─ 2. ShellExecuteW("open")
 ├─ 3. launchBrowserDirect()            直接起注册表里的浏览器 exe
 ├─ 4. launchBrowserDirect(forceNewWindow: true)   --new-window
 ├─ 5. openExternalFallback()           走 shell 的 start 关联
 └─ 6. 每步之后 _waitForBrowserWindow()：找**标题对得上这本书/这个平台**的窗口
       找到 → BringWindowToTop + SetForegroundWindow
       都找不到 → 如实说 + 地址进剪贴板
```

### 判定"页面真的打开了"的四道门（每一道都是被假阳性逼出来的）

| 假阳性 | 现象 | 现在怎么挡 |
|---|---|---|
| 挑到浏览器**辅助窗口** | 标题 `(标题为空)` | 要求**标题非空** |
| 挑到 **Electron 应用** | 类名也是 `Chrome_WidgetWin_1` | 要求**进程名**是浏览器 |
| 浏览器的"**还原页面**"提示 | 非空标题、同进程 | 要求标题**含书名前 4 字或平台站点名** |
| 页面没加载完 | 标题 `无标题 - 用户配置 1 - …` | 加进"空白页"特征表 |

★ **`ShellExecuteW` 返回 >32 只代表"请求交出去了"** ——
  进程起来了 ≠ 窗口出现了 ≠ 导航过去了 ≠ 加载完了。要断言就一路查到**标题**。

### 踩过并**撤回**的做法（都写在代码注释里，别重写）

| 做法 | 为什么撤回 |
|---|---|
| 用 `--user-data-dir` 起**隔离实例** | 全新 profile 会走浏览器首次运行流程 |
| 起点**窄窗启动页** | `file://` 页面上的 `window.open` 基本必被拦成空白页 |
| 用 `runas` 把浏览器**按提升权限**起起来 | 会弹 **UAC 框**（用户明确嫌弹窗多） |
| **替用户点掉**提权冲突框的「是」 | 那个按钮 = "用普通权限重启浏览器" → **把用户开着的窗口全关了**，代价远大于收益 |
| 用 `OpenProcess` 是否被拒来判断"对方提权" | 拿 explorer / svchost / pid 4 校准后**判据不成立**（SYSTEM 级的 svchost 照样打得开，`GetLastError()` 还会被后续 FFI 调用冲掉）→ 改**读令牌** |

### 关于 UIPI（浏览器以管理员身份运行）

浏览器提权常驻时，普通权限的程序**交不出 URL** —— Windows 的完整性级别隔离挡下，
浏览器会弹「现有实例正在以提升的权限运行，是否用普通权限重启？」
（窗口类 `#32770`、标题含 `Microsoft Edge`）。

程序**认出**这个框并**如实说**（不替用户点 —— 见上表），提示三个办法：
① 在框里点「是」；② 右键本工具 → 以管理员身份运行；③ 直接粘贴已复制的地址。

★ 查权限**只能读令牌**（`OpenProcessToken` + `GetTokenInformation(TokenElevation)`）。

## 2. 浏览器渲染通道（起点 www 多页靠它）

起点要抓 **500 条**（25 页 × 20）必须走 www 站多页，而 www 站有风控 ——
所以用**系统浏览器无头渲染**：`msedge.exe --headless=new … --dump-dom <url>`
（配一个**独立临时 profile**，不读用户 cookie / 登录态，抓完即删）。

- 与 HTTP 通道**共用**白名单 / robots / 限速器（渲染不是"绕开规矩的理由"）；
- `render` 严格串行（同一实例同时只跑一个浏览器进程）。

### 「浏览器产出空 DOM（exit=0）」

**这不是"没装浏览器"** —— 浏览器起来了却什么都没输出，
是它把请求**交接给了另一个已在运行的实例**、自己立刻退出
（最常见触发条件：那个实例**以管理员身份运行**）。

现在的处理：
1. **空 DOM 自动重试一次**（换全新 profile）—— 交接失败常常是瞬时的；
2. 错误文案自带排查方向（管理员身份 / 完全退出浏览器后再扫）；
3. 报告里**如实区分**"没找到浏览器内核"与"www 站多页未走通" ——
   原来无条件写"未检测到可用浏览器内核"是**谎报**，用户会去装一个已经装好的浏览器。

### 自检

```
网文扫榜工具.exe --selftest-render=r.txt out
```

打印：浏览器路径 / WebView2 版本 / 真实渲染耗时 / 解析到的行数。
★ 必须在**打包好的 exe** 里跑 —— `dart run` 起不了子进程，测出来是环境假象。

## 3. 起点**不再降级**

`QidianSource.fetch()` 现在的策略：**只走 www 多页；失败就如实报错**。

原来 www 失败会**静默降级**到移动站（每榜 20 条）。那更糟 ——
20 条冒充"这个榜的全部"会**进趋势、进导出、进对比**，
用户拿到的是"看起来完整、实际残缺"的数据。

- 没找到浏览器内核 → 直接报错（「装 Edge / WebView2 后即可抓 500 条」）；
- www 没走通 → 报错 + 失败原因 + 三条排查方向。
- `_fetchMobile` **保留但不再自动调用**（其他功能不变），标了 `unused_element`。

★ 一般原则：**"降级/兜底"分支要写"这次为什么降级"，不是"一般为什么降级"。**

## 4. 导出的图：画布宽 = 逻辑宽 × 缩放

`renderBoardImage` / `renderTrendImage` 的 `width` / `height` 一律当**逻辑尺寸**，
物理画布 = `逻辑 × Metrics.factor`（与建窗口同一套约定）。

原来画布写死 980、内容却乘 `Metrics.factor` —— 在 150% 缩放的屏上
列宽合计 1398 > 可用 908，走"硬约束压缩"时**书名列（stretch 列）第一个被压到下限**
（实测 314 → 54 像素，图里只剩一个字 + 省略号）。

## 5. 界面文本是**纯文本**，不许写 Markdown

`_toast` / `infoDialog`（系统 MessageBox）/ 状态栏 / 画布上的字
**一个都不解析 Markdown** —— 写 `**粗体**` 用户看到的就是两个星号。
已加回归：扫 `lib/**/*.dart`，字符串里出现 `**` 即失败（跳过注释与正则转义）。

## 6. 发布方式

- 发布包：`release/webnovel-rank-scanner-v<版本>.zip`（exe + `启动.cmd` + 使用说明）；
- 打包后**独立校验**：`zipfile.testzip()` 全过 + 解出来的 exe 与本地**逐字节比对**；
- 建 Release 用 **GitHub Actions 自带的 `${{ github.token }}`**
  （`.github/workflows/release.yml`，推 `v*` 标签触发）——
  **不需要在本地配 PAT**。
  ★ 坑：标签必须在 workflow 文件推上去**之后**重新推一次才会触发。
- **构建可复现**：同一份源码 → 逐字节相同的 exe（2026-10-03 实测 md5 一致），
  所以"发布包里的 exe"与"仓库里的源码"可以互证。
